1. What is the problem asking?

Given an array, find all unique combinations of 3 numbers whose sum is 0.

For example:

nums = [-1, 0, 1, 2, -1, -4]

Possible valid triplets are:

[-1, 0, 1]     → -1 + 0 + 1 = 0
[-1, -1, 2]    → -1 + -1 + 2 = 0

So answer:

[[-1, -1, 2], [-1, 0, 1]]
2. Why are you using Set<List<Integer>>?
Set<List<Integer>> st = new HashSet<>();

This is the most important part of your solution.

You don't want duplicate triplets.

For example, suppose your loops find:

[-1, 0, 1]
[0, 1, -1]
[1, -1, 0]

Mathematically, these are the same triplet.

But Java's List sees them as different:

[-1, 0, 1]
[0, 1, -1]
[1, -1, 0]

So you do:

Collections.sort(arr);

Now all three become:

[-1, 0, 1]

Then:

st.add(arr);

Since st is a HashSet, it keeps only one copy.

So:

ArrayList → stores one triplet
HashSet → removes duplicate triplets

3. Why three loops?

You need to select three different elements.

for(int i = 0; i < nums.length; i++)

selects the first number.

for(int j = i + 1; j < nums.length; j++)

selects the second number.

for(int k = j + 1; k < nums.length; k++)

selects the third number.

For example:

nums = [-1, 0, 1, 2]

The loops generate combinations like:

i=0, j=1, k=2
→ [-1, 0, 1]

i=0, j=1, k=3
→ [-1, 0, 2]

i=0, j=2, k=3
→ [-1, 1, 2]

i=1, j=2, k=3
→ [0, 1, 2]

Notice this:

j = i + 1
k = j + 1

This ensures you don't reuse the same index and don't check the same combination in reverse order.

4. Checking the sum

Inside the innermost loop:

if(nums[i] + nums[j] + nums[k] == 0)

You're checking:

first number + second number + third number = 0

For example:

nums = [-1, 0, 1]

Then:

-1 + 0 + 1

gives:

0

So we have found a valid triplet.

5. Creating the triplet

When you find a valid combination:

ArrayList<Integer> arr = new ArrayList<>();

You create a new list.

Then:

arr.add(nums[i]);
arr.add(nums[j]);
arr.add(nums[k]);

Suppose:

nums[i] = -1
nums[j] = 0
nums[k] = 1

Then:

arr = [-1, 0, 1]
6. Why Collections.sort(arr)?

This is specifically for handling duplicates.

Suppose the loops find:

1, -1, 0

You initially get:

[1, -1, 0]

After:

Collections.sort(arr);

you get:

[-1, 0, 1]

Now suppose another iteration gives:

[-1, 0, 1]

Both are exactly equal:

[-1, 0, 1]
[-1, 0, 1]

Therefore, the HashSet stores only one.

7. Adding to the Set
st.add(arr);

Suppose you find:

[-1, 0, 1]
[-1, -1, 2]
[-1, 0, 1]

The HashSet becomes:

[-1, 0, 1]
[-1, -1, 2]

The duplicate:

[-1, 0, 1]

is automatically ignored.

8. Why this return statement?

You have:

Set<List<Integer>> st

but your method says:

public List<List<Integer>> threeSum(int[] nums)

So you need to convert the Set into a List.

You wrote:

return new ArrayList(st);

It works, but I recommend using the generic type explicitly:

return new ArrayList<>(st);

So your final line should preferably be:

return new ArrayList<>(st);
Complete Flow

Think about your algorithm like this:

                  nums
                   |
                   ↓
             Pick 3 numbers
                   |
                   ↓
        Do they sum to 0?
              /        \
            NO          YES
            |            |
            ↓            ↓
         Ignore      Create List
                         |
                         ↓
                    Sort the List
                         |
                         ↓
                    Add to HashSet
                         |
                         ↓
                  Duplicate?
                   /       \
                 YES        NO
                  |          |
               Ignore       Store
                              |
                              ↓
                     Convert Set → List
In one sentence:

Your algorithm uses three loops to generate every possible triplet, checks whether its sum is zero, sorts every valid triplet so that the same combination has the same order, stores them in a HashSet to remove duplicates, and finally converts the set into the required List<List<Integer>>.

Complexity

For n elements:

Three nested loops → O(n³)
Sorting each valid triplet → technically O(1) because each triplet has exactly 3 elements
HashSet insertion → average O(1)

Therefore:

Time: O(n³)
Space: O(number of unique triplets)
